# AGENTS.md

ROBO Pro Coding projects (`.ft`) are scriptable here: generate, inspect, verify, and drive the
application without clicking. Read this before touching a project.

## `.ft` layout

A ZIP. Main-file entries carry a leading `/`; `lib/` entries do not. UTF-8, LF.

```
.project.json           uuid / name / mode / version / controller / unsaved
lib/controller.blockly  controller block = pin configuration
lib/controller.py       generated from that block
/<name>.blockly         main program
/<name>.py              Python mirror (regenerated by the app in blocks mode)
```

`mode`: `ADVANCED` (blocks) or `PROFESSIONAL` (Python only). Details: `docs/format.md`.

Everything here targets **ROBO Pro Coding 6.5.4**. The block data in
`src/ftgateway/data/` is a snapshot of that build; other versions may differ.

## Setup

```bash
pip install -e .            # provides `ftg`
ftg --version
```

No dependencies, Python 3.9+. Without install: `PYTHONPATH=src python -m ftgateway ...`.

## Commands

| intent | command |
|---|---|
| motor on M1 runs forever | `ftg gen motor-run --name X --speed 512` |
| LED blink / steady on M1 | `ftg gen led-blink --name X --hold 1` · `ftg gen led-on --name X` |
| pure Python project | `ftg gen python --name X` |
| validate | `ftg verify X.ft --strict` |
| inspect | `ftg info X.ft` · `ftg blocks motor` |
| edit one entry | `ftg get X.ft /X.py` · `ftg put X.ft /X.py new.py` |
| unpack / repack / rename | `ftg extract` · `ftg pack` · `ftg config --name` |

```python
from ftgateway import build_motor_run, verify
from ftgateway.blocks import ProjectBuilder
```

## Rules (each violation produces a broken project)

1. `loop_endless` takes statement input **`DO`**; `start_block` takes `statement`.
   A wrong name makes Blockly silently drop the children — an empty loop, no error.
2. `instance_name_0` / `direction_0` are indexed fields. The instance value is
   `<controller-block-id>-<pin-block-id>` from `lib/controller.blockly`; otherwise the field
   falls back to `-` and the code becomes `-.set_speed(...)`.
3. Only use block types present in `src/ftgateway/data/block-catalog.json` (pin hardware is in
   `hardware_types`). `ftg verify --strict` enforces this.
4. Speed is a `speed` value input with a `math_number` shadow block (field `NUM`).
5. Keep `<xml xmlns="https://developers.google.com/blockly/xml" version="23">`.

## Verify after every change

```bash
ftg verify OUT.ft --strict        # expect: RESULT: ALL CHECKS PASSED
python -m unittest discover -s tests   # after touching generation logic
```

## Bridge (optional, Windows)

Needed only to open a project in the app, screenshot it, or let the app generate code.

```powershell
.\bridge\launch.ps1 -Port 9334      # clears ELECTRON_RUN_AS_NODE, isolated profile
node bridge\setfile.js out.ft       # inject via DOM.setFileInputFiles (no OS dialog)
node bridge\verify_in_app.js ctrl.blockly main.blockly
```

Never start the app with plain `Start-Process` + flags: with `ELECTRON_RUN_AS_NODE=1` set, the
exe runs as `node`, parses the first argument as a JS file and exits instantly.

## After an app upgrade

```bash
node bridge/dumpblocks.js src/ftgateway/data/block-schema.json
```

## Do not

- Commit, push, or upload to a controller unless asked.
- Hand-edit `data/*.json` or `lib/controller.py` (both are generated).
- Assume a written file is valid — run `ftg verify`.
