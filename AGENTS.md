# AGENTS.md

Instructions for AI coding agents working with this repository.

This repository makes **fischertechnik ROBO Pro Coding** projects (`.ft`)
scriptable: they can be generated, parsed, verified and driven from Python,
without clicking through the GUI.

---

## 1. What `.ft` is (do not guess)

`.ft` is a ZIP archive:

```
.project.json           metadata: uuid / name / mode / version / controller / unsaved
lib/controller.blockly  controller block = pin configuration
lib/controller.py       Python generated from that block
/<name>.blockly         main program (Blockly XML)
/<name>.py              main program Python (regenerated by the app in blocks mode)
```

`mode` is `ADVANCED` (blocks) or `PROFESSIONAL` (Python only).
Full details: [docs/format.md](docs/format.md).

## 2. Setup

```bash
git clone <this repo>
cd robo-pro-coding-run-api-gateway
pip install -e .          # gives you the `ftg` command
ftg --version
```

No third-party dependencies. Python 3.9+.

If you cannot install, use `PYTHONPATH=src python -m ftgateway ...`.

## 3. Everyday commands

| intent | command |
|---|---|
| motor on M1 keeps running | `ftg gen motor-run --name Motor_Run --speed 512` |
| LED on M1 blinks | `ftg gen led-blink --name LED_Blink --hold 1` |
| LED on M1 stays on | `ftg gen led-on --name LED_On --speed 512` |
| pure Python project | `ftg gen python --name PyProgram` |
| inspect a project | `ftg info FILE.ft` |
| validate | `ftg verify FILE.ft --strict` |
| find a block | `ftg blocks motor` / `ftg blocks 超声波` |
| edit one entry | `ftg get FILE.ft /Name.py` / `ftg put FILE.ft /Name.py new.py` |
| unpack / repack | `ftg extract FILE.ft dir/` / `ftg pack dir/ out.ft` |
| rename project | `ftg config FILE.ft --name NewName` |

Python API:

```python
from ftgateway import build_motor_run, verify
from ftgateway.blocks import ProjectBuilder

build_motor_run("Motor_Run", speed=512).save("Motor_Run.ft")
print(verify("Motor_Run.ft", strict=True))
```

## 4. Hard rules (violating these produces broken projects)

1. **`loop_endless` uses the statement input `DO`, not `statement`.**
   `start_block` is the one that uses `statement`. A wrong name makes Blockly
   silently drop the children — the loop looks empty, with no error.
2. **Pin instance ids are `<controller-id>-<pin-block-id>`.** A motor block's
   `instance_name_0` must equal the id pair from `lib/controller.blockly`
   (`<block type="txt4_controller" id="…">` + `<block type="motor" id="…"/>`),
   otherwise the dropdown falls back to `-` and the code becomes
   `-.set_speed(...)`.
3. **Never invent block types.** They must exist in
   `src/ftgateway/data/block-catalog.json` (pin hardware lives in
   `hardware_types`, not `block_types`). `ftg verify --strict` enforces this.
4. **Field names are indexed**: `instance_name_0`, `direction_0`; the speed
   value input is `speed` with a `math_number` shadow block (field `NUM`).
5. Keep XML header `<xml xmlns="https://developers.google.com/blockly/xml" version="23">`,
   UTF-8, LF line endings, main-file entries prefixed with `/`.

## 5. Verification loop (always run it)

```bash
ftg verify OUT.ft --strict        # container, metadata, XML, statement names, Python syntax
```

Expected tail: `RESULT: ALL CHECKS PASSED`.

When you changed generation logic, also run the test suite:

```bash
python -m unittest discover -s tests      # 13 tests
```

## 6. Driving the real application (optional, Windows)

Only needed when the user wants the app itself to open a project, render it,
or generate code. Requires the app installed.

```powershell
.\bridge\launch.ps1 -Port 9334       # clears ELECTRON_RUN_AS_NODE, own profile
$env:CDP_PORT = 9334
node bridge\setfile.js out.ft        # opens the project in the app (no OS dialog)
node bridge\verify_in_app.js ctrl.blockly main.blockly   # parse + generate code
node bridge\cdp.js shot shot.png     # screenshot proof
```

Why the launcher exists: `ELECTRON_RUN_AS_NODE=1` makes the exe behave like
`node`, so every argument is parsed as a JS script and the app exits at once.
Never start the app with raw `Start-Process` + flags.

The "load project" stepper ends in a real `<input type=file>`; feed it with
`DOM.setFileInputFiles` (`bridge/setfile.js`) instead of typing into a dialog.

## 7. Refreshing the block data after an app upgrade

```bash
node bridge/dumpblocks.js src/ftgateway/data/block-schema.json
```

`block-schema.json` holds 314 blocks with their inputs, fields and the Python
each block emits. Do not hand-edit it.

## 8. Do not

* Do not commit or push unless the human asks.
* Do not upload to a controller automatically — the user runs the program from
  the app (upload support is on the roadmap).
* Do not edit `lib/controller.py` and expect it to stick; the app regenerates it
  from `controller.blockly`.
* Do not assume a project is valid because the file was written — verify it.
